# AI 开发工作流

AI Dev Workstation 提供了一个结构化的环境，旨在促进人类开发者与多个 AI 代理之间的协作。

## 3-标签页策略

默认的 `ai_workstation` 布局围绕三个阶段的认知过程设计：**推理 (Reasoning)**、**实现 (Implementation)** 和 **执行 (Execution)**。

### 标签页 1: 核心代理 (推理与架构)
**重点:** 高级规划、文档查找和架构决策。

*   **左面板 (Gemini):** 用于广泛的知识检索、文档解释和算法设计。Gemini 的大上下文窗口使其非常适合保持“整个项目”的上下文。
*   **右面板 (Claude):** 用于复杂的推理、架构评估和重构策略。Claude 擅长“思考”问题。

**工作流:**
1.  将问题陈述粘贴到 Claude 中。
2.  让 Gemini 查找相关文档或库。
3.  在编写任何代码之前综合出一个计划。

### 标签页 2: 辅助支持 (实现)
**重点:** 生成代码、编写测试和特定功能的实现。

*   **Codex/Copilot CLI:** 用于生成样板代码、单元测试或特定的功能块。
*   **OpenCode:** 一个辅助助手，用于审查代码片段或提供替代实现。

**工作流:**
1.  从标签页 1 获取计划。
2.  让 Codex 生成骨架代码。
3.  复制代码到剪贴板。

### 标签页 3: 终端 (执行)
**重点:** 文件管理、Git 操作和运行服务器。

*   **Shell:** 标准命令行。用于运行测试、启动服务器或管理文件。
*   **Git (LazyGit):** 一个全屏 UI，用于管理 Git 提交、分支和差异。

## 典型循环

1.  **启动:** `of start my-project` (打开 Windows 编辑器 + AI 终端)。
2.  **标签页 1:** 与 Claude 讨论功能。商定接口。
3.  **标签页 2:** 生成实现细节。
4.  **Windows 编辑器:** 粘贴代码，优化并保存。
5.  **标签页 3:** 运行测试 (`npm test` / `cargo test`)。使用 LazyGit 暂存和提交更改。
6.  **循环:** 重复。
